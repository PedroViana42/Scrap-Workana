# Radar PostgreSQL

PostgreSQL is the official persistence layer for Radar. SQLite is not used as a production fallback and the old local `vagas.db` is not part of the Radar schema.

## IDs

Tables use `BIGINT GENERATED BY DEFAULT AS IDENTITY`.

This keeps local operations simple and predictable. Radar does not need globally distributed IDs at this stage.

## Domain And ORM

Domain dataclasses such as `Job`, `Deal`, `SourceConfig`, and `CompanySource` remain independent from SQLAlchemy.

Repositories map domain objects into SQLAlchemy models and keep persistence details inside `radar/database`.

## PostgreSQL Types

`metadata`, `raw_data`, and source capabilities use `JSONB` for flexible structured data.

`jobs.technologies` uses `ARRAY(TEXT)` with a GIN index because future filtering by technology should be efficient and idiomatic in PostgreSQL.

`company_sources.tags` uses `JSONB` instead of an array so the catalog can later evolve from simple string tags into richer source-specific metadata without changing the column type.

Money fields use `NUMERIC(14, 2)` and map to Python `Decimal`.
